# Commands

Every command accepts `--config <path>` (default: `openapi-gen.config.mjs`). Running `openapi-gen` with no command is the same as `openapi-gen generate`.

| Command | What it does |
|---|---|
| [`run`](#run) | Interactive setup wizard — start here |
| [`add`](#add) | Add another API to an existing config |
| [`generate`](#generate) | Generate all files from the config (`--prune` removes stale ones) |
| [`diff`](#diff) | Compare the spec against the files on disk, without writing |
| [`init`](#init) | Write a commented starter config |

`--version` prints the installed version and `--help` lists everything above.

## `run`

```bash
npx openapi-gen run
```

The wizard looks at your project first — `package.json`, `app/` or `pages/`, `src/` — and uses what it finds as defaults, so most questions are just <kbd>Enter</kbd>:

1. **Framework** — `nextjs`, `nextjs-pages` or `react`, detected from your project (for `react`, also the hooks library: `react-query` or `fetch`)
2. **API name** — a label shown in CLI output
3. **OpenAPI spec** — URL or local path. It's loaded right away: you see the API title and number of operations, or a clear error (e.g. *"this is the Swagger UI page, use /api-json"*)
4. **Path prefix to strip** — suggested from your spec (e.g. every path starts with `/api`)
5. **Backend URL** — env variable name and fallback URL (Next.js only). The fallback defaults to the spec's server
6. **JWT cookie name** — leave blank to skip auth
7. **Generate now?**

Output folders follow your layout (`src/app/api` or `app/api`, `src/services` or `services`). At the end the wizard offers to chain into [`add`](#add). If the config already exists, it asks before overwriting.

::: tip
Answers can be piped, which is handy in scripts: `printf 'nextjs\nmy-api\n./openapi.json\n\n\n\n\ny\nn\n' | npx openapi-gen run`
:::

## `add`

```bash
npx openapi-gen add
```

Adds another API to the config. It asks for a name, the spec (validated like in `run`), auth (keep / override / `-` to disable), output folders and, for Next.js, the backend env variable.

- Each new API gets **its own folders** by default (`src/app/api/<name>`, `src/services/<name>`), so files from different APIs never overwrite each other.
- It reuses the `apiClient.ts` / `fetchBackend.ts` generated by the first API.
- The entry is **inserted into your file as text** — your comments and formatting are kept.

## `generate`

```bash
npx openapi-gen generate
npx openapi-gen generate --prune
```

1. **Validates** every entry — including typos, e.g. `unknown option "routeOut" — did you mean "routesOut"?` Nothing is written if something is wrong.
2. **Loads** every spec.
3. **Plans** every file first. If two APIs would write the same file, it stops before writing anything and lists the conflicting files.
4. **Writes** `apiClient.ts`, `fetchBackend.ts`, route handlers, services and hooks.
5. **Reports stale files** — generated files whose endpoints were removed from the spec. With `--prune` they are deleted (along with empty folders). Only files that start with the `Auto-generated by codegen-openapi` header are ever considered, so your own files are never touched.
6. **Checks packages** — if the generated code imports something missing from your `package.json`, it prints the install command for your package manager (npm, pnpm, yarn or bun):

```
! The generated code needs packages that are not in your package.json:
    pnpm add js-cookie server-only
    pnpm add -D @types/js-cookie
```

The command exits with code `1` when something fails, so it can run in CI.

## `diff`

```bash
npx openapi-gen diff
```

Loads the specs and shows, without touching the disk, which files would be **added** and which generated files are **no longer in the spec**:

```
[my-api] (nextjs) https://api.example.com/api-json
  + 2 new route file(s) not yet generated:
    + src/app/api/payments/[id]/route.ts
    + src/app/api/webhooks/route.ts
    8 unchanged
  ✓ 4 service(s) up to date

- 1 generated file(s) no longer in the spec:
    - src/app/api/legacy/users/route.ts

Run npx openapi-gen generate to apply changes (add --prune to delete removed files).
```

## `init`

```bash
npx openapi-gen init
```

Writes a starter config with every field documented in comments, using your project's folders. Does nothing if the file exists. For a first setup, [`run`](#run) is usually faster.
